## 1. 为什么是浏览器扩展，不是命令行工具

需求是"像提交 GitHub 一样批量提交文件"，使用者是不写代码的管理员。

| 方案 | 问题 |
|---|---|
| Python/Node CLI | 要装运行时、要输密码、要教命令行 |
| 本地 GUI（tkinter/Electron） | 要打包、要处理更新、文件选择器体验一般 |
| Chrome 扩展（选中） | 浏览器已经有了；复用登录态；不用装环境 |

## 2. 为什么是 content script，而不是 popup / service worker

- **popup**：一旦点开别处就关闭，长任务会被中断；而且 popup 的请求是 `chrome-extension://` 源，跨源带 Cookie 受 SameSite 限制，容易莫名其妙 401。
- **service worker（MV3）**：会被浏览器回收，传 1GB 文件的请求可能半路被杀。
- **content script**：运行在 `in.upcshare.cn` 的页面里，`fetch('/api/upload')` 是**同源请求**——Cookie 自动带、没有 CORS、没有 SameSite 问题，生命周期跟页面一致。

代价：面板是在别人页面里注入的 DOM，必须用 Shadow DOM 隔离样式（见第 5 条）。

## 3. 为什么不用密码

站点自己的登录 Cookie 就是凭据。扩展不碰密码带来三个好处：

1. 密码不落在任何文件/配置里，卸载即失效；
2. 用户在网页上退出登录，扩展立刻失效；
3. 仓库可以公开，不怕泄漏。

**红线：任何"为了方便"而加密码输入框、把 token 存 localStorage、或者要求用户粘贴 Cookie 的改动，都不要做。**

## 4. 为什么单文件、零构建

`content.js` 约 2500 行，一个 IIFE，没有打包器、没有依赖、没有 npm。

- 使用者可以直接在 `chrome://extensions` 里点"检查视图 → 控制台"改一行就试；
- 审计成本低——"这个插件会不会偷我东西"看一眼就够；
- 避免为 3 个功能引入 webpack/vite 这类会过期的工具链。

代价：没有模块化。纯函数集中在文件顶部并挂到 `globalThis.__UPC_BATCH__`，就是为了不引入模块系统也能单测。

## 5. 为什么用 Shadow DOM

站点是 Vue 3 + 全局 CSS（`style.css` 4000 多行）。直接往页面里插 DOM，必然被站点的 `button/table/input` 样式污染。

实现：`<div id="upcshare-batch-host">` + `attachShadow({mode:'open'})`，样式全部写在 shadow 内的 `<style>` 里。
宿主机 `pointer-events:none`，只有按钮和遮罩是 `auto`，不影响页面原有交互。

两个坑（已踩过）：

- `hidden` 属性会被 `.upc-overlay{display:flex}` 这类作者样式覆盖，所以样式表里必须有 `[hidden]{display:none !important}`；
- 站点有明暗主题（`document.documentElement.dataset.theme`），面板用 `MutationObserver` 跟随。

## 6. 为什么用 XHR 而不是 fetch

`fetch` 没有上传进度事件。`xhr.upload.onprogress` 是浏览器里唯一能拿到"已传字节数"的标准途径。
不要"现代化"成 fetch + ReadableStream —— Chrome 里请求体流式上传的支持并不通用。

## 7. 限速的数学

Nginx：`rate=6r/m`，`burst=3`。令牌桶等价于：

- 前 3 个请求立即放行（burst）；
- 之后每 10 秒补 1 个令牌。

所以 `Pacer(3, 10500)`：容量 3、补充间隔 10.5 秒（留 5% 余量）。100 个文件 ≈ 3 个立即 + 97 × 10.5s ≈ 17 分钟。

**不要**改成"并发 5 个猛灌"：`limit_conn 2` 会直接 429，反而更慢，而且会给站点留下坏流量。
如果将来站点放宽限速，把 `PACE` 改成可配置即可（不要写死成 0 延迟）。

## 8. 查重：以站点为唯一真相

不维护本地台账（曾经写过又删了），原因：

- 上传成功的文件立刻出现在 `/api/admin/files?status=pending` 里；
- 本地台账会和站点状态漂移（用户在后台删了文件、台账还记着）；
- 站点索引一次拉取覆盖 500 多条，成本可接受。

判定：

| 情况 | 标记 | 行为 |
|---|---|---|
| 同名 + 同大小 | `dup` | 默认跳过（可取消勾选强制重传） |
| 同名 + 不同大小 | `dupname` | 标黄，**不自动跳过**（可能是新版本） |
| 扩展名不在白名单 | `unsupported` | 红色，不参与上传 |
| > 200MB | `toolarge` | 红色（插件收紧；站点实际允许 1GB） |
| 文件名非法字符 | `badname` | 红色 |

## 9. 路径 → 学科/目录的启发式

`webkitRelativePath` 的第一段是用户选中的文件夹名，本身有歧义：可能是课程名，也可能是"我的资料"这种容器。

策略（`splitRelativePath`）：

1. 先拿第一段去和站内已有的学科分类名比对（归一化：去空格/标点/全半角/大小写，站内全量，实测 93～95 个，会波动）；
2. 命中 → 第一段就是学科，其余是目录；
3. 没命中 → 拿第二段再比；
4. 都没命中 → 第一段是已知容器名（`我的课程资料`、`总目录`、`files`、`下载` 等）时，第二段才是学科；否则**第一段就是学科**，其余全部拼成多级目录。

   v0.3.5 修正：以前三层以上一律把第二段当学科，导致站内学科表里没有的课程（`工业现场总线技术`、`精密机械设计基础`）被误判成 `附件/子目录`。现在根目录默认就是课程，只有明确的容器名才下钻。

**这是启发式，不是事实**。UI 允许逐组修改，用户手改永远优先。改这里必须同步改 `selftest.js` 的 5 个路径用例。

## 10. 失败重试

| 状态 | 是否重试 | 间隔 |
|---|---|---|
| `429` | 是 | 15s × 第几次 |
| `5xx` / 网络错误（status 0） | 是 | 4s × 第几次 |
| `4xx`（400/401/403/404/413） | 否 | 直接标失败 |

最多 4 次。`413` 不重试——文件就是太大，重试没意义。

## 11. 有意识没做的事

| 没做 | 原因 |
|---|---|
| 拖拽文件夹 | `webkitGetAsEntry` 递归要在 `drop` 事件里同步取 entry，复杂度不低；先让 `input[webkitdirectory]` 跑通 |
| 并发 > 1 | 站点 `limit_conn 2`，并发没有收益 |
| 断点续传文件 | 站点不支持分片上传，单文件只能整传；重传靠查重跳过 |
| 自动删除/撤回 | 属于危险操作，留给后台 |
| 上传完成后自动刷新后台列表 | 站点是 SPA，跨页面状态打通收益低 |

## 12. 学科/目录：为什么自己写组合框，不用 `<datalist>`

学科分类的候选来自 `/api/categories`（站内全量）。子目录的候选**只**来自"这门课在站内真实用过的目录 +
本次已经建出来的目录"（纯函数 `dirOptions`）——`/api/subcategories` 会忽略 `category` 参数返回全站 36 个
目录名，掺进下拉里就是"每门课都看得到别人课的『课设参考』"。

没用原生 `<input list>` + `<datalist>`，原因有三条：

1. **Shadow DOM 支持不稳**：弹层由浏览器原生渲染，Chrome 在 Shadow DOM 里的定位和交互出过多次问题，不能作为长期依赖。
2. **加不了“新建”项**：需求是“列表里没有就直接用输入值”，datalist 没有插入自定义操作行的能力。
3. **样式不可控**：深浅色主题、最大高度、高亮项都没法改，和面板视觉不统一。

自己写的组合框（`fuzzyFilter` + `dirOptions` + 一个 `position:fixed` 的共享菜单）代价是几十行代码，换来：模糊排序（完全 > 前缀 > 包含 > 子序列）、键盘导航、输入法 composition 不打断、自由输入即新建。

新建的学科/目录只作用于本次会话：不写 `localStorage`，刷新即清空，和状态全部在内存里的设计一致（第 8 条）。

## 13. 与站点导航的关系

站点导航的「上传资料」本来就跳 `/admin`。插件**不拦这个跳转**：点击瞬间先把面板盖上去（避免原站上传表单一闪），路由、地址、导航高亮全部交给站点自己。

- 内容脚本拿不到 Vue Router 实例，也 hook 不到主世界的 `pushState`，所以用一次 300ms 的地址轮询把面板和路由对齐：进入 `/admin` 打开，离开就 `closePanel(true)` 关闭并清空。直接刷新/收藏 `/admin` 也会打开面板。
- 早期版本用 `history.pushState` 自己改地址，结果 Vue Router 的内部路由没变，点「资料库」（目标就是当前路由）被判成重复导航、地址停在 `/admin`。**改地址必须由路由器来做。**
- 面板是「导航栏下方、宽 1120px 居中、高度随内容」的页面，不是拉满 100vh 的遮罩；顶部导航始终可见可用。**没有悬浮按钮，也没有 ×**——退出方式就是点导航去别的页面。
- 全屏模式复用原站上传页的入口语义（`/admin`），为以后把面板并入站点（PR）留了路由挂载点。
- 管理员专属的「自动通过审核」对非管理员同时隐藏 + disabled，代码里也再次校验 `state.me.is_admin`。

## 14. 为什么是「课程 → 目录 → 文件」三栏

v0.2 把所有东西压进一张表，结果是：课程在每一行重复、目录和文件混在列里、上传按钮和勾选框并列，第一次打开不知道从哪下手。用户反馈的三个问题（操作顺序、概念、视觉密度）其实是同一个：**没有把课程当成上下文**。

v0.3 改成三栏；v0.3.9 把「先选课程」那一屏并进来，全站只有**一个视图**：

- **课程栏三合一**：课程输入框本身就是组合框 —— 下拉选站内已有课程（94 门全量、可打字模糊搜索）、直接输入新名字即新建；旁边一个「从文件夹导入」。原来那块独立的「选择课程」空状态页删掉了，因为它和工作台顶部重复：空状态有选课/建课，工作台也有课程框和「更换课程」。
- **选中已有课程时**：从站内索引读取该课程已有的目录，只建空目录，不导入已有文件；目录候选来自真实落盘记录。手打全名后失焦也按「选中」处理。
- **没填课程名不拦人**（v0.3.9 的原始决定，**v0.3.22 被推翻**）：可以先建目录、先拖文件，只把上传置灰。后来用户连着三轮反馈指向同一条——空子目录可以无限叠、每次动作都伴随一行像报错的提示，"先不拦"换回来的只有乱。现在改成**没选学科分类就建不出子目录**，见第 19 条。
- **引导不常驻**：1-2-3 步骤条和格式说明放在右侧工作区（还没有目录时），有内容就自动收起。
- **导入确认放在选完之后**：点「从文件夹导入」直接开系统选择器，选完弹「检测到 N 个文件、M 个目录，将生成课程「X」」再确认。原来先弹一页"请先整理好"的确认，用户点了才知道规模；现在防呆还在，且信息是真的。多门课程仍进课程选择弹层。
- **顶部课程**：只出现一次。课程名可搜索/新建，改名即时生效；从下拉切到别的课程会先 `confirm` 再清空当前目录与文件。
- **左侧目录**：当前课程的目录列表，点选切换；底部「＋ 新建目录」。
- **右侧文件**：只显示当前目录的文件，支持拖入、选择、移除、失败重试。
- **底部队列**：待传/已完成计数、「上传设置」、「全部上传」。上传时展开进度和日志。

参考的成熟交互：

- [Uppy Dashboard](https://github.com/transloadit/uppy)：拖拽、逐文件进度、暂停/继续/重试、继续加文件。
- [FilePond](https://github.com/pqina/filepond)：状态和动作贴着文件条目，键盘可操作。
- [Cloudreve](https://github.com/cloudreve/cloudreve)：左侧目录、右侧文件列表，上传任务独立显示。

数据模型从 `state.groups` 改成：

```js
state.course = { name, dirs: [{ name, files: [] }] }
state.activeDir = course.dirs[i]
```

关键取舍：

- **课程是单数**：一次会话聚焦一门课；选文件夹检测到多门课时弹层让你选一门，其余可以再导一次。这样课程不用在每行重复。
- **目录名就是上传的 sub_category**：改名会改落盘路径，所以没有单独的“显示名”。
- **每目录上传 + 全部上传**：`collectDirTargets` / `collectCourseTargets` 都产出同一形状的 target，`runTargets` 不需要知道是哪种范围。
- **运行态锁定**：上传中禁用课程/目录编辑、增删、拖拽，只留“停止”，避免循环里的目标引用悬空。
- **已完成不被查重重置**：`applyIndex` 跳过 `done` / `running`，否则上传后索引重新应用会把已完成改成“已存在”。
- **拖拽只收文件**：拖文件夹递归需要 `webkitGetAsEntry`，留到以后；现在拖文件到当前目录足够解决“随手补几个文件”。

鲸鱼图标来自 [Simple Icons](https://github.com/simple-icons/simple-icons) 的 DeepSeek 图形（CC0），只做装饰，不代表与 DeepSeek 有任何关联。

## 15. 换课 vs 改名，以及权限边界（v0.3.10 起）


**换课和改名必须分开。** 课程输入框同时承担两件事：给当前课改名、切到另一门课。判断依据不能是"当前 `state.course.name`"——点下拉之前一定先触发过 `input`，实时值早就等于目标课程了，于是永远判定成"没换课"，旧课程的目录就留在左栏（这正是用户报的"课程和目录没有完全同步"）。现在的基准是**进入输入框那一刻**记下的 `state.courseFocusName`：和它相同算改名，不同且命中站内课程算换课（换课前确认，然后清空重建）。失焦也走同一判定，所以手打全名换课同样生效。

**目录以课程为单位单独取。** 站点没有"按课程取目录"的接口（`/api/subcategories` 忽略 `category`，实测过），只能 `GET /api/files?category=X` 分页拉文件再聚合（`loadCourseDirs` + 纯函数 `dirsFromItems`）。这样顺带拿到每个目录的文件数，也不再依赖全局索引扫描的覆盖范围。站内没有空目录的概念，没有文件的目录查不到——这是数据模型的限制，不是 bug。

**权限边界放在 UI 和服务端两处。** `DELETE /api/admin/files/{id}` 本身只认管理员，所以 UI 的门禁是为了不让人点了才报 403，不是为了安全：

| 动作 | 普通成员 | 管理员 |
|---|---|---|
| 新建目录 | ✅ | ✅ |
| 去掉本次刚建、没传过文件的目录 | ✅「从本次列表移除」 | ✅ 同一个入口 |
| 改站内已有目录的名字 | ❌ 不给入口 | ❌ 不给入口 |
| 删站内已有目录 | ❌ 没有这个操作 | ❌ 没有这个操作 |
| 看「已有资源」列表 | ❌ 按钮都不给 | ✅ |
| 删除站内文件 | ❌ | ✅ 且必须点两次确认 |

判定用纯函数 `dirHasUploaded(dir)`：`fromSite`（从站内带出来的）或里面有 `done`/`running` 的文件，就算"站内已有"；`canRenameDir()` 和 `canRemoveDir()` 都是它的取反。

**"删除目录"这个入口被删掉了。** 一开始按用户要求给管理员留了「删除目录」，后来用户指出关键事实：**站点没有目录这个实体，目录是文件路径推出来的**——把一个目录里的文件全删掉，这个目录在服务器上就自动消失了。所以"删目录"点了什么也不会发生（我们只能把那一行从本次列表里去掉，站内原样），是个假动作。现在站内目录的菜单里只剩「上传本目录」，要清掉一个目录就去「已有资源」把它的文件删完，`dropEmptiedSiteDir()` 会在最后一个文件删掉时把这一行收掉，跟服务器保持一致。

**不能改名的时候，不要给任何"好像可以改"的反馈。** 第一版只把 ⋯ 里的「重命名」去掉，但点标题仍然会展开下拉、仍然会弹出那行"改这里即时生效"的说明——用户一句"这在不能改名的时候是不应该出现的"就指出了这个半成品状态。现在 `openMenu()` 开头 `if (input.readOnly) return`（focus、click、方向键三条路一起堵掉，只拦 focus 是不够的），提示行也不再靠聚焦出现；原因改成写在常驻的 meta 行末尾（`… · 站内已有，不可改名`），不需要用户点一下才知道。

**删除站内文件是这里唯一不可逆的操作**，所以做成两段式：第一次点变成「确认删除？」，4 秒内不点第二下自动取消。

**目录行的操作收进 `⋯`。** 右区顶部原来横着挂「上传本目录」「删除」两颗按钮，跟目录本身隔了一栏，看着不像对这个目录做的事。现在当前目录行右侧常驻「上传（N）」，其余操作在 `⋯` 里：上传本目录 / 重命名 / 删除目录。

**改名只对「本次新建的目录」开放，且不设"保存"按钮。** 站点根本没有改目录名的接口：改一个站内已有的目录，
只是让本次上传落到一个新名字上，站内旧目录原封不动，结果是同一门课多出两个意思相近的目录——用户说得很直接，
"反正没留接口"。所以 `canRenameDir(dir)` 就是 `!dirHasUploaded(dir)`：站内带出来的、或本次已经传过文件的目录，
名称输入框只读、聚焦时不展开下拉（`openMenu()` 开头 `if (input.readOnly) return` 一次性堵掉 focus / click /
方向键三条路；只读标题的聚焦还会用 `stopImmediatePropagation` 拦掉 `bindCombo` 的监听，所以这个监听必须注册在它之前）、
⋯ 菜单里也不出现「重命名」。
可改的那些目录，改它不调用任何接口，只是决定 `sub_category` 写什么，所以没有"提交"这回事；
用户找不到保存入口的根源是缺反馈，于是编辑时下方出现一行说明，失焦或回车后名字真的变了就记一行日志
「子目录名已改成「X」，本次上传会落到这个子目录。」

**文件直接挂在课程下的课也要看得见。** `sub_category` 为空串不是"没有目录"，而是一个真实存在的目录（课程根目录，实测站内 455 个文件在这里）。所以 `dirsFromItems` 把空串也聚成一个条目，界面上显示为「根目录」，`已有资源` 查询时照样带上 `sub_category=`（空串是有效筛选，省略它会查出整门课）。

**目录候选只给本课的。** 早期 `comboPool('subCategory')` 是"本课目录优先 + 全站 36 个目录名兜底"，实际效果是每门课的下拉里都混着「课设参考」「作业汇报参考」这种别人课的东西，用户反馈"别索引全部课程的"。现在换成纯函数 `dirOptions()`：只给这门课在站内真实用过的目录 + 本次已经建出来的目录；想新建就直接输入，下拉里仍有"使用「x」（新建）"。

**下拉的定位要按"提示行已经出现"来算。** 目录名的下拉贴着整条 `.upc-work-head` 的下沿展开，而不是贴着输入框，否则会盖住输入框下面那行改名说明。前提是**改名提示的 focus 监听必须注册在 `bindCombo` 之前**——监听器按注册顺序执行，反了的话定位那一刻那一行还是 `display:none`。

刻意没做：

| 没做 | 原因 |
|---|---|
| 持久化课程/文件 | 刷新后 `File` 对象必然失效，存名字没有意义；界面提示“别刷新” |
| 多目录并发上传 | 站点限速按 IP，并发只会更快撞 429 |
| 拖拽文件夹递归 | 复杂度高，先保留“从文件夹导入” |
| 文件级改名 | 上传用原文件名，改名容易和站点查重/路径预期打架 |

## 16. 为什么最后把外层卡片也拆了（v0.3.15）

前面每一轮都在往"像站点自己的页面"靠，但外层始终是一块带边框、圆角、阴影的白色卡片，顶上还有一条带分隔线的"批量投递 upcshare"标题栏——那是对话框的画法，也正是外挂感的来源。

对照站点自己的 CSS（`--bg:#f5f5f7` 页面底色、`--surface:#fff` 卡片、`--border:rgba(0,0,0,.06)`、`--radius-md:12px`、`--shadow-sm:0 1px 3px rgba(0,0,0,.04)`、`.container{max-width:1120px;padding:0 24px}`）就能看出差别：站点的页面是**标题 + 若干块卡片**，不是"一整块卡片里再塞一个窗口"。

所以全屏模式下：面板本身透明（无边框、无圆角、无阴影、不裁剪），标题变成 20px 的页面标题，课程栏、目录栏、文件区、底部队列各自是一块站点样式的卡片，之间留 14px 间距，整页跟着页面滚动（遮罩层 `overflow:auto`，导航栏仍然是 sticky）。这样「上传资料」看起来就是站点多了一个页面，而不是页面上浮了一个工具。

代价：面板不再是固定高度的窗口，内容多时整页滚动。下拉和 `⋯` 菜单都用 `position:fixed` 定位，所以不受影响；但**滚动时的手感只能真人验证**，无头测试测不出来。

补一刀（v0.3.17）：拆掉外框后暴露出另一个问题——面板高度是"内容撑出来的"，只有两三个文件时下半屏是一片空白底色，看着像页面没加载完。现在改成应用外壳的节奏：面板 `min-height:100%`，中间那一行（目录栏 + 文件区）`flex:1` 吃掉剩余高度，内容多时卡片内部自己滚（`.upc-dirs` / `.upc-files` 都是 `flex:1;overflow:auto`），窗口太矮时保留 320px 最小高度、整页还能滚，不会把队列卡挤没。用 `min-height` 而不是 `height` 是有意的：内容真多时页面仍然可以往下长，而不是把内容锁死在一屏里。


## 17. 术语跟站点走：学科分类 / 子目录（v0.3.19）

`docs/pr-readiness.md` 里唯一留给用户拍板的项，答案是**跟站点走**。上游 `Upload.vue` 的两个字段标签是
「学科分类」和「子目录」，我们之前全程叫「课程」和「目录」——自己用没问题，一旦要长成站点自己的页面，
同一块界面上两套名词就是硬伤。所以本轮把所有**用户可见文案**（标签、placeholder、菜单项、日志、
`confirm`、`title`/`aria-label`）统一成「学科分类 / 子目录」。

三条边界，别改错：

- **代码内部不改**：`state.course` / `addDir` / `dirTitle` 这些变量名、函数名和解释"为什么"的注释保留原样。
  改名只增加 diff 噪音，而且"课程"在开发者脑子里确实比"学科分类"短。
- **数据不改**：`isContainerName()` 里比对的 `'我的课程资料'`、`'课程资料'`、`'课程文件'`、`'总目录'`
  是用户硬盘上真实存在的文件夹名，动了就破坏路径折算。
- **「根目录」这个词留着**：文件直接挂在学科分类下（`sub_category` 是空串）时，左栏那一行仍显示「根目录」。
  站点没有给这种情况起名，输入框的 placeholder 改成「子目录名称（可选，留空 = 直接挂在学科分类下）」把意思说清楚，
  比硬造一个"未分子目录"更好读。

同轮顺手统一了字号：标题里的 `upcshare` 之前固定 12px，现在 `font-size:inherit`，跟「批量投递」一样大；
学科分类栏的标签、输入框、导入按钮统一到 14px，按钮内边距照抄输入框的算式（6px 上下 + 1px 边框），
两个框同高（35px），不再一个胖一个瘦。输入框从 210px 加到 260px，因为新 placeholder 更长。

## 18. 「还差什么」那行提示的触发边界（v0.3.20）

合并空状态（第 14 条）之后，"没选学科分类"这件事全靠课程栏下面那行小字说明。当时的条件是
`invalid && (total > 0 || dirs.length > 0)`——只要有待传文件**或**已经有子目录就提醒。

第二个分支是多余的，而且有害：点「＋ 新建子目录」在没选学科分类时本来就该成功（这是第 14 条定的产品决定），
结果目录建成的同一帧，上方立刻出现一行琥珀色小字"请先填写或选择学科分类名称，才能开始上传"。
它说的是上传，但用户刚做的动作是新建，于是被读成"新建被拒了，得先选课程"。
位置也加重了这个误读：那行在课程栏下面、正好在"这个框上面"。

现在收紧成 `invalid && total > 0`：**只有真的有文件等着传、而上传又点不了时**才说这句话，
并且文案点名是哪个按钮——「文件先收下了，但「上传」还点不了：先在上方选择或输入一个学科分类。」
"先收下了"三个字是必要的：它明确告诉用户刚才那一步成功了，缺的只是下一步。

一般化的结论：**解释"某按钮为什么是灰的"的提示，触发条件必须和那个按钮的可用性同源**（这里就是 `total > 0`），
挂在别的状态上就会在用户做出成功动作的瞬间发出失败信号。

## 19. 没选学科分类就不给建子目录（v0.3.22，推翻第 14 条里那条"先不拦"）

v0.3.9 定的是"拦在第一步最劝退，所以什么都不拦，只把上传置灰"。三轮反馈之后发现它换来的是另一种劝退：

1. 空子目录可以无限叠（第 14 条的"先建着"没有上限）——用户连点五次，左栏出现五行同名目录；
2. 每做一次"其实还没法上传"的动作，就要多解释一次为什么不能上传（第 18 条那行提示）；
3. 这些目录最后都得上一次学科分类才能用，中间状态纯属借来的。

所以改成：**子目录必须挂在某个学科分类下，没选分类就建不出子目录**。落点很窄，只有三处：

- `updateQueue()` 里那颗按钮的 `disabled` 条件从"只看 `state.running`"改成"或 `invalid`"，
  并给 `title` 写明原因（「先选择或输入一个学科分类，再建子目录」）；
- `.upc-add-dir[disabled]` 去掉 hover 的高亮、光标换成 `not-allowed`——禁用态必须看起来就是禁用态，
  否则又是"看得见但点不动"那个坑；
- `addDir()` 内部同源再判一次（`safeSegment(state.course.name)`），给键盘和其它调用路径兜底，
  拒绝时把焦点送回学科分类输入框并写一行日志。`addFilesToActive()` 里 `addDir()` 可能不生效，
  所以后面补了 `if (!state.activeDir) return`——不加这行就是一次 TypeError。

**为什么不是"点了弹报错"**：禁用 + 就地说明原因，比让用户先做错再挨一句红字好；而且工作区的引导
（「先在上方选择或输入学科分类，再新建子目录，然后把文件拖进来」）本来就在说同一件事，不需要再加一处喊话。

**为什么从文件夹导入不一起拦**：导入会自己从文件夹层级识别出学科分类，它本来就是"绕过手输"的正路，
拦掉它等于把最顺的那条路堵了。

第 18 条那行提示的边界仍然成立，只是触发面变窄了：现在它只在"有分类时建不出问题、把分类清空后
还剩着文件"这种真需要解释的情况下出现。

## 20. 界面只有两档盒子（v0.3.25 → v0.3.27）

**背景**：用户连着四轮挑同一排的毛病——先"框的格式对齐"，再"框的样式也要对齐，四个不同样子的框很难看"，
再"四个字体样式都不一样"。量出来确实是：圆角 8/10/7/5/0 五种、字号 14/12.5/12/11/15 五种、
高度 19/21/26/30/34/35/38 七种，`.upc-btn` 一个类被 `.small` 和 `.upc-coursebar` 各改一次。
**同一区域被反复投诉，就该怀疑规则本身而不是一处一处补**——这里缺的是一份规格。

**决定**：面板里的可操作盒子只允许两档，圆角一律 8px（容器卡片 10px、状态标签 999px 另算）：

| 档 | 高度 | 字号/字重 | 底色 + 描边 | 用在 |
|---|---|---|---|---|
| 主操作 | 插件 35px / Vue 42px | 14px·600 / 15px·600 | 软底 + 1px 实线（主按钮实心蓝，但同一套盒模型） | 学科分类输入框、从文件夹导入、全部上传、停止 |
| 次级 | 插件 34px / Vue 32px | 13px·500 | 软底 + 1px 实线 | 已有资源、上传设置、新建子目录（虚线保留） |
| 行内 | 不套盒子 | 13px | 无底无框，只点亮文字 | 目录行的「上传（N）」与 ⋯、文件行 × |

**「查看文件夹导入规范」为什么从第三个盒子改成「?」徽标（v0.3.27）**：它和前两个不是同一类动作——
前两个是"我要做这件事"，它只是"这件事的说明书"。并排摆成第三个盒子，等于把说明抬到了和动作一样的地位，
用户还得再读一遍三种文字才知道点哪个。现在它是贴在「从文件夹导入」右上角的一颗 20px「?」，
悬停或键盘聚焦时浮出 tooltip「查看文件夹导入规范」，点开还是那份可复制的规范。
左边那颗「学科分类」文字标签同时去掉：placeholder 已经说明这一栏是什么，
无障碍名字改挂在输入的 `aria-label` 上。

**代价与兜底**：徽标只有 20px，比一颗按钮小，所以必须同时满足"键盘 Tab 走到 + 有 aria-label + 有 tooltip"，
不能只靠鼠标悬停发现——这三条都写进了断言（插件 `smoke.mjs` 4b4，Vue `ui-check.mjs` 13/14）。
另外两档规格不是靠自觉守的：`smoke.mjs` 4b2/4b3 与 `ui-check.mjs` 20/21 每次都量真实
`getBoundingClientRect` / `getComputedStyle`，将来谁再随手加第三种圆角或字号，测试直接红。

## 21. 拖文件夹走导入识别，以及结果导出（v0.3.28）

**拖进来的文件夹为什么不塞进当前子目录**：用户拖一个文件夹，意图是"按这个结构分好类"，
不是"把它们倒进我现在选中的这一行"。所以 `receiveDrop()` 判断含目录就走 `importFiles()`，
和点「从文件夹导入」共用同一套 `buildGroups` 折算与"看得见规模"的确认；只拖纯文件才 `addFilesToActive`。

**为什么 relPath 要保留根目录名**：`input[webkitdirectory]` 给出的 `webkitRelativePath`
第一段就是被选中的文件夹名。拖拽这边把根名也留成第一段，两条入口的产物才逐字节一致，
"拖与选结果相同"这条验收才是真的，而不是靠两边各写一遍相似逻辑。

**两个必须记住的 API 细节**：`webkitGetAsEntry()` 只能在 `drop` 事件的同步阶段调用（异步里返回 null）；
`FileSystemDirectoryReader.readEntries()` 一次最多返回 100 条，必须循环读到空数组，
否则大文件夹会被静默截断——这类"少传了但没有任何提示"的问题最难发现。

**结果导出 CSV**：传一半断掉时，屏幕上几十行状态不如一张表在 Excel 里筛。
`exportCsv(rows)` 是纯函数（BOM + CRLF + 逗号/引号/换行转义），列固定为
`relPath,category,sub_category,status,id,error`；下载用 `Blob` + `URL.createObjectURL`，
不落任何持久化（与第 8 条一致：状态只在内存，导出只是把当前内存快照写出去）。
`Blob.text()` 解码会吃掉 BOM，所以断言按字节量前三码点 EF BB BF。
§20 的四档字号同样由断言守着（面板里出现第五种字号直接红）。
