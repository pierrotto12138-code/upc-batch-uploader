## 正文（可直接粘贴）

你好，我是学校的学生，也是 upcshare 的用户。先说一句实话：**这个平台让课程资料第一次有了"学长传下来、学弟找得到"的地方，谢谢你做了它。** 这个 issue 不是来提要求的，是来问方向的。

### 我做了什么

因为一学期攒下来的课件、试卷、实验报告有上百个，站点一次只能传一个文件，我在本地给自己做了一个 Chrome 扩展（MV3 内容脚本）：选一个文件夹，按层级自动拆成「学科分类 / 子目录」，比对站内已有记录去重，然后排队批量传。

它**只调用你现有的接口**（`/api/upload`、`/api/admin/approve/{id}`、`/api/files`、`/api/admin/files`、`/api/categories`），**没有改动站点一行代码**，也不打算改它的任何规则。目前自己用了挺久，27 个纯逻辑单测 + 41 项端到端断言。

（这里放一张面板截图：`preview.png`。注意先按最后一节脱敏。）

### 想问的三件事

这三条都是产品决策，我不替你定，所以先问：

1. **上传限速放哪儿？** 站点 Nginx 是 `6r/m + burst 3 + 并发 2`。我把令牌桶做在了客户端（先放 3 个、之后每 10.5 秒一个），所以批量传不会把 429 打到你服务器上去。如果这个"客户端自律"你认可，我可以把它一起搬进上游；如果你觉得限速策略该由服务端统一管、不希望前端各自实现，那我把 Pacer 留在扩展里，PR 里就不带它。
2. **`/admin` 这个页面想让位吗？** 现在 `/admin` 挂的是 `Upload.vue`（单文件上传）。批量视图如果要做进站点，最自然是**替换**那一页（保留单文件模式作为默认标签），或者加个 `?mode=batch` 共存。哪种都行，但这是"改你的页面"，得你点头我才动手。
3. **"上传即自动通过审核"是不是你鼓励的？** 扩展里有这么个开关，**仅管理员可见、默认关闭**（UI 按 `me.is_admin` 门控，服务端本身也有鉴权）。但我理解站点的人工审核可能就是为了把关质量，所以如果这个能力不该进官方实现，我会从 PR 里去掉，只保留"批量传完留在待审核队列里"。

### 顺带附上几个接口实测现象

都是我在实现过程中撞到的，**不确定是有意为之还是小疏漏**，列出来供参考，不需要为此改任何东西：

| 现象 | 我的实测 | 我怎么绕的 |
|---|---|---|
| `GET /api/subcategories` 好像忽略 `category` 参数 | 带不带 `category=` 都返回同一批（36 个）目录名 | 想要"某门课用过哪些子目录"，只能 `GET /api/files?category=X` 分页拉文件自己聚合 |
| `GET /api/admin/files?status=pending` 是**全站**范围 | 传 `category=` 不生效，会混进别的学科分类的文件 | 客户端拿到之后自己按 `category` + `sub_category` 过滤 |
| README 里写的 `POST /api/admin/scan` | 我在代码里没找到这个映射，请求也不通 | 没依赖它 |
| README 让配 `APP_COOKIE_DOMAIN`，`docker-compose.yml` 里转发的是 `COOKIE_DOMAIN` | 按 README 配的话，跨子域的登录态会失效 | 只是记录，我这边用不到 |
| `GET /api/files` 的 `sub_category=`（空串） | 是**有效筛选**，能筛出直接挂在学科分类下的文件（实测 455 条） | 这个行为很好用，我只是确认它是有意的 |

### 如果方向对得上

我这边可以直接搬过去的，是那些和界面无关的部分：路径层级 → 学科分类/子目录的折算、模糊匹配站内学科名、按「学科分类/子目录」作用域的查重键、令牌桶限速器，以及这 27 个用例的单测。界面我打算按站点的组件习惯重写成 Vue（`CoursePicker` / `DirRail` / `FileDrop` / `QueueBar`），颜色圆角直接吃你 `style.css` 的 token，不另起一套。

**你不感兴趣也完全没关系**，这个扩展我自己用得很好，代码我也可以按 MIT 放出来给同学自己装。要不要并进取决于你。

打扰了，谢谢你做这个网站。
